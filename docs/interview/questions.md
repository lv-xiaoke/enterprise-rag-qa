# 面试追问与回答线索

| 追问 | 回答要点 |
|---|---|
| 为什么选这个项目？ | 企业知识与个人事务形成可演示闭环，可以展示前端状态、后端权限、AI 工具和持久化的协同。 |
| 为什么 Cookie 会话而不是 JWT？ | 服务端撤销简单，浏览器使用 HttpOnly，同源配合 CSRF；代价是每次鉴权查库及会话存储。 |
| 为什么 SameSite 还要 CSRF？ | SameSite 是一层防护；写请求再验证 Origin 与绑定 Cookie 的 token，登录也检查。 |
| 模型说自己是管理员怎么办？ | 模型输出不改变服务端身份；角色来自数据库，个人工具仍检查当前员工。 |
| SSE 为什么用 fetch？ | 需要 POST 请求体和主动取消，fetch 能读取 ReadableStream；解析不能假定网络分片就是一个事件。 |
| 为什么还存 messages？ | checkpoint 是图状态，不适合作为稳定页面业务契约；messages 支持分页、状态和引用历史。 |
| 重复点击会不会重复收费？ | 同会话 client_request_id 唯一、运行锁拒绝并发；不自动重放不确定请求，用户先查历史。 |
| 停止会立即终止费用吗？ | 尽力取消后续任务；无法保证上游或已运行同步工具撤销，不承诺费用回滚。 |
| BM25 和向量如何融合？ | 中文 bigram 分词，BM25 词面、向量语义；RRF 用排名避免分数量纲问题。 |
| 文档更新会混入旧版吗？ | 新版处理成功才更新指针，两路检索共用有效版本集合；失败保留旧版。 |
| 为什么每次重建 BM25？ | 小语料第一版选择明确的一致性与简单实现，代价是查询开销；扩大后改缓存代次与原子换快照。 |
| 如何防文档提示注入？ | 文档被当作不可信资料，工具权限在程序中；提示词不能证明安全，仍需对抗测试。 |
| 指标是不是准确率？ | 文件 Hit@k 是来源命中；答案正确性、证据支持、拒答分别测，真实模型指标尚未实测。 |
| 怎么扩展多进程？ | 共享取消控制与任务队列、数据库级并发约束、索引一致性、文件共享；当前单进程范围明确。 |
| Agent 写的代码你负责什么？ | 坦诚说明 AI 辅助开发，自己理解需求、架构、取舍和测试，能定位问题与完成小改动；不虚构独立手写。 |

练习时用实际文件与失败测试解释每一个回答，不背未经验证的吞吐、成本节约或企业上线经历。
