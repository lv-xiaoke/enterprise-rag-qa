## 这些结果代表什么

评测通过认证 API 运行真实业务图、工具、业务数据库和 Chroma，读取实际运行轨迹评分。脚本模型控制语义输出；玩具 embedding 控制本地检索输入。因此结果表示执行器正确处理这些固定输入，不表示真实模型工具选择准确率、语义检索质量或完整回答事实准确率。

task_completed 字段表示“该场景预期行为达成”，包含正确追问、正确拒绝和正确失败，不能改名为“所有业务请求成功率”。权限分数检查另一员工的金丝雀数据不出现在返回中；它与工具读取前的授权断言、资源所有权测试共同构成证据，单靠模型说“拒绝”不足以证明安全。

本次仅完成两条制度问题的真实模型烟雾验证，未完成系统性的真实模型专项评测。页面测试曾因配置切换绕过替身而意外调用已配置模型；该意外请求不计作效果评测。已修正测试模型注入，并在 API 测试 fixture 禁用真实凭证，避免遗漏替身导致外部调用。

## 场景分布与指标

制度 6、本人数据 6、缺参/非法参数 6、多步骤 8、权限 6、上下文/恢复 4、故障 4。开发与留出标签用于隔离后续调参；已根据完整脚本集调试执行器，不能把本次脚本结果称为独立的真实模型留出成绩。

工具选择比较实际尝试的工具集合；按 tool_call_id 和 attempt 配对开始与结果，只用同次成功调用验证成功场景的参数；查询前必须已有成功的身份结果。完成同时检查 HTTP、运行终态、业务状态、必要成功工具结果与标注答案片段，不能把一次被拒绝调用的参数拼到另一次成功调用上。失败和超时保留在分母。该规则评分只覆盖已标注行为，不替代人工事实审查。

## 独立审查后的修复

六项 Important 问题均建立复现测试并修复：阻塞读取、当前证据裁剪、退出失败清理、中断后的状态刷新、硬重启轨迹、评分跨调用误关联。另补充取消终态与迟到轨迹写入的竞态验证。

同步数据库和检索工作各有独立的两槽容量，不在事件循环直接执行，不无限排队；数据库另有连接/语句/锁等待边界。已经超时的只读工作不会被重复启动，也不会发布迟到证据。Python 不能安全强杀正在运行的线程，因此依赖卡住时保留其槽位，后续同类请求明确返回繁忙；个人数据与知识查询容量隔离。检索的 embedding 工作移出文档版本锁，避免拖住文档管理。

本轮问题和实际成功工具证据优先保留，旧历史使用剩余字节预算；超出 32,000 字节则明确报 CONTEXT_LIMIT。工具开始在操作之前提交，结果在展示之前提交；重启为未配对的开始补记 interrupted，不补造成功。运行已经终止后，条件写入拒绝迟到的轨迹更新。

## 复现

```powershell
python -m pytest tests -q
python -m eval.run_agent_eval --dataset eval/agent_cases.jsonl --mode deterministic
```

每次创建新的 `runtime/agent-eval/<时间戳与随机后缀>`，保留数据库、向量库及 results.json，不删除已有数据。评测仅使用模拟制度和员工数据，不向用户既有知识库上传内容。

以下命令会调用配置的真实模型并产生费用；完整留出集当前尚未系统运行：

```powershell
python -m eval.run_agent_eval --dataset eval/agent_cases.jsonl --mode live --split heldout
```

live 模式排除 execution_only 的非法模型输出夹具，使用同一隔离模拟业务环境；玩具 embedding 的结果不能衡量生产语义检索质量。评测指标应结合逐题轨迹人工审查，工具的等价安全拒绝路径需要单独核对。
